Validation results (2026-11-05):
- Both release archive SHA-256 checks passed.
- pip check passed. Runtime imports and runner --help passed.
- Seven IMU unit tests passed.
- ARM64 bridge test: ALL PASS after fixture warmup adjustment.
- ONNX inference: both models return finite 29-joint actions; 1000 measured
  samples each. e24 p99 11.33 ms, e13 p99 13.98 ms under concurrent CPU load,
  against a 20 ms policy period. See logs/inference-benchmark.json.
- e24 full real-model G2 grid: 36 ground runs, zero falls and zero aborts.
  G3 ground transitions: 3/3 complete, zero aborts. Slack profile fails knee
  velocity limits. Overall report therefore says FAIL; do not call it a full
  gate pass. Same-model training parity was not rerun (needs training setup).
- End-to-end DDS simulator did NOT pass: its Python simulator runs at 0.14x
  real time here, and the runner entered damping in STANDBY_PRE. Treat this
  simulator as unsuitable for wall-clock controller validation on this host.
  This does not establish real-robot failure or readiness. Use a faster
  simulator host / optimize the simulator before relying on a full DDS test.
- All controller/simulator processes were stopped after testing.

Hardware acceptance still required with G1 powered on: received state/rate,
correct mode and no competing publisher, remote stop, bridge watchdog on
actual hardware, suspended interpolation/HOLD, thermal readings, and real
control-loop timing. Read the upstream operator procedure before motion.

Slow DDS simulator investigation:
The same Unitree G1 MJCF without DDS ran 1500 physics/PD steps (3 simulated
seconds) in 0.238 s compute: 12.59x unpaced real time, p99 step 0.359 ms.
This was a simple held-pose benchmark, not the entire dance. Combined with
working 50 Hz inference and 500 Hz C++ bridge tests, it points to the Python
DDS simulator integration/threads rather than insufficient raw physics
compute. Individual callback/GIL/logging costs have not yet been profiled.
See logs/physics-benchmark.json. Hardware timing still needs acceptance.

Direct nominal standby gate also passed: ground, zero delay, nominal gains,
no added torso mass, friction 1.0. Completed 60 s PRE + dance + 30 s POST,
zero falls/aborts, PRE/POST tilt error maxima 2.61/2.53 degrees. This is one
nominal test, not the full standby perturbation grid. Its success without
Python DDS supports the simulator-integration bottleneck diagnosis.
